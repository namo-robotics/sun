## Purpose and scope

The initial compatibility goal is:

> A newer Sun compiler can consume an unchanged library produced by an older
> supported Sun compiler, on a compatible target, without rebuilding the
> library's existing compiled implementations.

Generic bodies may still be specialized by the consuming compiler. Their
compatibility contract is specified separately below.

This draft covers Sun-to-Sun boundaries in programs and libraries, including
functions, types, global storage, callbacks, and compiler runtime services.
[C interoperability](/c-ffi) continues to follow the selected platform C ABI.
A stable Sun ABI does not make arbitrary C calls safe.

| Scenario | Proposed guarantee |
| --- | --- |
| New compiler imports an older supported bundle | Warn and continue when generated contract checks pass |
| Old compiler imports a newer bundle | Supported only if its formats, semantics, ABI, and required capabilities are understood |
| Library rebuilt with changed implementation or API | A distinct artifact; interchangeability is not promised |
| Replace a library beneath an existing executable | Outside the initial guarantee |
| Import code for a different architecture or platform ABI | Rejected unless a compatible payload exists |
| Arbitrary future compiler imports every historical bundle | No unlimited support commitment; supported revisions must be published |

Cross-compiler compatibility and library evolution are different promises.
Library evolution would additionally specify which changes to an existing
library preserve compatibility with its already compiled consumers.

## Status

This draft retains compile-time specialization and exact dependency identity.
Machine-level calling conventions and runtime contracts remain unresolved.
The [conformance page](/abi/conformance) defines the work required before a stable
revision can be published.
