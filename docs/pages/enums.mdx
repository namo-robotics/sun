# Enums

Enums define a type with a fixed set of named variants.

import { Callout } from 'nextra/components'

## Defining an Enum

```sun
enum Color { Red, Green, Blue }
```

Each variant is automatically assigned an integer value starting from 0:
- `Red` = 0
- `Green` = 1
- `Blue` = 2

## Using Enums

### Variables

Declare variables with an enum type and access variants using dot notation:

```sun
var c: Color = Color.Green;
```

### Comparison

Enum values can be compared with `==` and `!=`:

```sun
function is_red(c: Color) bool {
    return c == Color.Red;
}

function main() i32 {
    var c: Color = Color.Blue;
    if (c != Color.Red) {
        return 1;
    }
    return 0;
}
```

## Enums as Function Parameters

Enums can be passed to and returned from functions:

```sun
enum Direction { Up, Down, Left, Right }

function opposite(d: Direction) Direction {
    if (d == Direction.Up) { return Direction.Down; }
    if (d == Direction.Down) { return Direction.Up; }
    if (d == Direction.Left) { return Direction.Right; }
    return Direction.Left;
}

function main() i32 {
    var dir: Direction = Direction.Up;
    var opp: Direction = opposite(dir);
    if (opp == Direction.Down) {
        return 1;
    }
    return 0;
}
```

## Multiple Enums

You can define multiple enums in the same file:

```sun
enum Status { Pending, Running, Completed }
enum Priority { Low, Medium, High }

function main() i32 {
    var s: Status = Status.Running;
    var p: Priority = Priority.High;
    return 0;
}
```

## Enums in Classes

Enums can be used as field types in classes:

```sun
enum TaskStatus { Pending, InProgress, Done }

class Task {
    var status: TaskStatus;

    function init() {
        this.status = TaskStatus.Pending;
    }

    function start() void {
        this.status = TaskStatus.InProgress;
    }

    function complete() void {
        this.status = TaskStatus.Done;
    }

    function is_done() bool {
        return this.status == TaskStatus.Done;
    }
}
```

## Pattern Matching with Enums

Combine enums with `match` expressions for clean branching:

```sun
enum Color { Red, Green, Blue }

function to_rgb(c: Color) i32 {
    return match c {
        Color.Red => 0xFF0000,
        Color.Green => 0x00FF00,
        Color.Blue => 0x0000FF,
        _ => 0
    };
}
```

See [Match Expressions](/match) for more details.

## Payload-Carrying Variants

Variants can carry data, turning an enum into a tagged union:

```sun
enum Shape {
    Circle(f64),          // radius
    Rect(f64, f64),       // width, height
    Empty
}

var c = Shape.Circle(2.5);
var r = Shape.Rect(3.0, 4.0);
```

The only way to reach a payload is a `match` with a destructuring pattern,
which binds each payload position to a fresh immutable local (use `_` to skip
a position):

```sun
function area(s: ref Shape) f64 {
    return match s {
        Shape.Circle(r) => 3.14 * r * r,
        Shape.Rect(w, h) => w * h,
        Shape.Empty => 0.0
    };
}
```

Matches on enums are checked for exhaustiveness: every variant must be
covered, or a `_` arm must be present. The error names the missing variants.

Rules for payload enums:

- They are value types, passed by `ref` like classes and returned by value.
- `==` / `!=` are not defined on them — `match` is the eliminator.
- Payload types may be primitives, pointers, other enums, and classes
  without `deinit`. References, arrays, and recursive payloads (without
  `raw_ptr` indirection) are rejected.
- Payload-free enums are unchanged: plain `i32` values with `==` comparison,
  usable in `extern "C"` signatures. Payload enums cannot cross the C
  boundary yet.

<Callout type="info">
  Not yet supported: generic enums (`Option<T>`), nested patterns, arrays or
  globals of payload enums, and payloads owning heap resources. These are
  planned follow-ups.
</Callout>

## Trailing Commas

Trailing commas are allowed in enum definitions:

```sun
enum Days {
    Monday,
    Tuesday,
    Wednesday,
    Thursday,
    Friday,
    Saturday,
    Sunday,
}
```
