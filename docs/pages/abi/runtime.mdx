# Runtime & Errors

Part of the [Sun ABI draft](/abi). Requirements are proposed, not guarantees of
current releases. **MUST**, **MUST NOT**, and **SHOULD** express draft requirements.
Unresolved decisions must be completed before stabilization.

## Runtime, errors, and global state

Runtime entry points referenced by compiled code MUST have versioned contracts,
including argument and result representations, ownership, and failure behavior.
Linking multiple bundles MUST NOT silently select incompatible implementations
of the same runtime symbol.

Error propagation MUST define the exception object, type identification,
matching, cleanup, and unwinding conventions. Unwinding through a boundary is
permitted only when both sides support its contract. The initial ABI MUST either
specify cross-bundle throwing and catching or explicitly reject unsupported
throwing boundaries; it cannot leave their behavior implicit.

Global initialization MUST run dependencies before their consumers, and MUST
initialize each deduplicated global instance once. Shutdown ordering, initialization
failure, thread-local state, and runtime state shared among bundles require
explicit rules. Bundling several runtime implementations MUST NOT duplicate
state that the ABI defines as process-wide.

**Unresolved:** inventory emitted runtime symbols, exception machinery, type-ID
collision handling, startup functions, teardown, and thread-local storage.
