# Declarations & Symbols

Part of the [Sun ABI draft](/abi). These are proposed requirements, not guarantees
of current releases. Open decisions must be resolved before stabilization.

## Declaration and symbol identity

A bundle refers to exact dependency artifacts. Rebuilding a dependency does not
make the new artifact a valid replacement for the old one.

| Subject | Level | Requirement |
| --- | --- | --- |
| Declaration identity | MUST | Include the defining artifact and portable declaration identity. |
| Local naming | MUST NOT | Let aliases, import order, or local names change a declaration's identity. |
| Nominal types | MUST NOT | Treat types from different artifacts as interchangeable just because their names or layouts match. |
| Exported symbols | MUST | Read or reproduce the producer's symbol names, including when current naming defaults differ. |
| Specialization identity | MUST | Include the generic declaration, enclosing specialization if present, and concrete arguments in order. |
| Duplicate specializations | MUST | Check ABI and generic semantics compatibility before merging definitions. |
| Private declarations | MUST | Keep declarations used by exported generic bodies in the import contract, even when source code cannot name them. |
| Global storage | MUST | Preserve one identity when several dependency paths reach the same global. |

## Open decisions

Specify the portable-key encoding, symbol spelling, specialization encoding, and
collision handling. Content hashes distinguish artifacts; they do not prove
that types, layouts, or behavior are compatible.
