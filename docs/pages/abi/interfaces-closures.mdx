# Interfaces & Closures

Part of the [Sun ABI draft](/abi). These are proposed requirements, not guarantees
of current releases. Open decisions must be resolved before stabilization.

## Interfaces and closures

Adding or reordering interface methods can break compatibility. A fixed method
table cannot contain every future specialization of a generic method.

| Subject | Level | Requirement |
| --- | --- | --- |
| Interface dispatch | MUST | Define method-slot identity, order, signatures, receiver adjustment, and metadata or destruction entries. |
| Generic methods | MUST | Define how interface methods are specialized. |
| Closure calls | MUST | Define whether the hidden argument points to the environment or to a closure record. |
| Private environments | MUST | Keep an environment layout private only when consumers never inspect it and invocation and cleanup use compatible interfaces. |
| Borrowed captures | MUST NOT | Let a capture outlive the value it borrows. |

## Open decisions

Specify method-table generation, interface reference passing and returning, and
closure capture destruction. Interface borrow parameters and return values
currently use different lowering rules; describing both as fat pointers is
insufficient.
